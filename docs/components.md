# Описание компонентов

Названия компонентов совпадают с названиями блоков на схеме `architecture.png`.

| Компонент | Назначение | Технология | Взаимодействует с |
| --- | --- | --- | --- |
| Менеджер отеля (браузер) | Клиент менеджера: вносит дневные показатели, смотрит KPI, задаёт пороги и читает отзывы своего отеля. Без него данные не попадают в систему | Веб-браузер | Frontend (UI) |
| Аналитик сети (браузер) | Клиент аналитика головного офиса: сравнивает отели, смотрит сезонность и прогнозы, выгружает отчёты. Работает только на чтение | Веб-браузер | Frontend (UI) |
| Гость (браузер) | Клиент гостя: оставляет оценку и отзыв. Источник данных о качестве обслуживания | Веб-браузер (в том числе с телефона) | Frontend (UI) |
| Администратор (браузер) | Клиент администратора: создаёт отели и пользователей, назначает менеджеров. Отдельная роль, чтобы управление доступом не смешивалось с аналитикой | Веб-браузер | Frontend (UI) |
| Frontend | Показывает дашборды, графики, формы ввода показателей и отзывов; отправляет запросы к API и хранит JWT-токен; не принимает решений о правах доступа | React, TypeScript, библиотека графиков | Backend: Guards (HTTPS, JSON) |
| Guards (JWT + RBAC) | Единая точка проверки: подпись и срок токена, роль пользователя, принадлежность отеля менеджеру. Если убрать — любой пользователь сможет читать и менять чужие данные | NestJS Guards, JWT | Все модули backend, Auth |
| Auth | Проверяет логин и пароль, выдаёт JWT. Нужен, чтобы идентифицировать пользователя без хранения сессий на сервере | NestJS, bcrypt, JWT | Users, Guards, Repository |
| Users | Хранит пользователей и их роли, связь «менеджер — отель». Основа для разграничения прав | NestJS | Auth, Hotels, Repository |
| Hotels | Карточки отелей: название, город, звёздность, номерной фонд (`rooms_total`). Номерной фонд нужен для проверки, что занятых номеров не больше, чем есть | NestJS | Users, Metrics, Repository |
| Metrics | Принимает дневные показатели (вручную или из CSV), проверяет их, считает загрузку и RevPAR, записывает в БД; после записи проверяет пороги. Центральный модуль системы | NestJS | Hotels, Notifications, Repository |
| Analytics | Считает KPI за период, сезонность, рейтинг отелей; для прогноза и сегментации обращается к ML-сервису. Отделён от Metrics, чтобы тяжёлые расчёты не мешали приёму данных | NestJS | Metrics, ML-сервис (HTTPS, JSON), Repository |
| Reviews | Принимает отзывы гостей, запрашивает тональность, пересчитывает средний рейтинг отеля. Отвечает за «голос гостя» в оценке эффективности | NestJS | Hotels, Analytics, Repository |
| Notifications | Сравнивает новые показатели с правилами оповещений и отправляет письмо менеджеру. Работает в фоне, чтобы не задерживать ответ пользователю | NestJS | Metrics, Почтовый сервис (SMTP), Repository |
| Reports | Формирует отчёт для выгрузки (Excel) по выбранным отелям и периоду. Нужен аналитику для передачи данных руководству | NestJS, библиотека работы с Excel | Analytics, Repository |
| Controller | Первый слой модуля: принимает HTTP-запрос, разбирает параметры, проверяет формат тела запроса (DTO), передаёт данные в Service и возвращает ответ | NestJS Controller, class-validator | Guards, Service |
| Service | Второй слой модуля: бизнес-логика (расчёт загрузки и RevPAR, правила проверки, решения об оповещении). Не знает про HTTP и про SQL | NestJS Service | Controller, Repository (Prisma ORM), другие модули |
| Repository (Prisma ORM) | Третий слой: единственное место, где backend формирует запросы к БД; обеспечивает транзакции и защиту от SQL-инъекций | Prisma | Service, PostgreSQL (SQL) |
| PostgreSQL | Хранит пользователей, отели, дневные показатели, отзывы, правила оповещений и оповещения с ограничениями целостности (`UNIQUE`, `CHECK`, внешние ключи). Доступна только backend | PostgreSQL | Только Repository (SQL) |
| ML-сервис (Python, FastAPI) | Прогноз загрузки, сегментация отелей и определение тональности отзывов (модели из лабораторных по анализу данных). Вынесен отдельно, так как использует Python и scikit-learn | Python, FastAPI, scikit-learn | Analytics (HTTPS, JSON) |
| Почтовый сервис (SMTP) | Доставляет письма о нарушении порогов; свою почтовую инфраструктуру мы не поддерживаем | SMTP-провайдер | Notifications |

## Основные таблицы БД

| Таблица | Основные поля | Ограничения |
| --- | --- | --- |
| users | id, email, password_hash, role (`manager` / `analyst` / `guest` / `admin`) | UNIQUE (email) |
| hotels | id, name, city, stars, rooms_total, manager_id → users | rooms_total > 0 |
| daily_metrics | id, hotel_id → hotels, date, rooms_occupied, adr_som, marketing_spend_som, cancel_rate, revenue_som | UNIQUE (hotel_id, date); CHECK 0 ≤ rooms_occupied ≤ rooms_total |
| reviews | id, hotel_id → hotels, rating (1–5), text, sentiment, created_at | CHECK rating BETWEEN 1 AND 5 |
| alert_rules | id, hotel_id → hotels, metric (`occupancy` / `rating`), threshold | один порог на метрику и отель |
| alerts | id, rule_id → alert_rules, metric_id → daily_metrics, sent_at | — |
